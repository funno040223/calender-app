# 生活管理アプリの画面構成と予定調整

2026-11-20。日々の予定を進めながら、食事を選ぶ手間を減らし、外出後も余力が残る暮らしを支える。この目的に対して、画面と配置処理を一緒に評価する。以下の画面配置・比較順序はこのアプリ向けの提案。

## iOSの設計指針をどう使うか

Appleはタブを主要な行き先として整理し、短い名前、タブ間を往復したときの状態保持、階層内での自然な戻り方を重視している。ホームに各専用画面の機能をすべて複製すると、それぞれの役割が伝わりにくくなる。[Appleのナビゲーション設計講義](https://developer.apple.com/videos/play/wwdc2022/10001/)・[Tab bars](https://developer.apple.com/design/human-interface-guidelines/tab-bars)

操作の名前には、押した結果を予想できる言葉を使う。視覚的な強弱、余白、グルーピング、短いラベルで関係を伝える。文字の拡大、読み上げ名、タップによる代替操作を考慮する。Webアプリにこれらの設計原則を適用する。[Design principles](https://developer.apple.com/design/human-interface-guidelines/design-principles/)・[Writing](https://developer.apple.com/design/human-interface-guidelines/writing)・[Gestures](https://developer.apple.com/design/human-interface-guidelines/gestures)・[Accessibility](https://developer.apple.com/design/human-interface-guidelines/accessibility)

| 場所 | 導線案 | 操作の意味 |
|---|---|---|
| ホーム | 「いま／一日」をタップまたは左右スワイプ | 「いま」で朝食を記録、「一日」で当日の流れを見る。現在のページ名を表示。画面端からの戻る操作を保つ |
| 予定 | 上部の「カレンダー／タスク」をタップ | それぞれ独立した画面とURLを維持。カレンダー内の横移動は日付送り専用。3日・週の横移動、月の縦移動、予定編集を保持する |
| 料理・運動 | 下部にそれぞれ固定タブ | 予定がない日でも買い足しや運動の見本を直接開ける |
| 記録 | 下部に固定タブ。全体→睡眠・食事・運動などの詳細 | 睡眠と当日の活動を並べて見返せる。料理・運動から同じ履歴を開き、二重集計を防ぐ |
| 設定 | 各タブの最上位画面の右上に同じ歯車。「設定」の読み上げ名を付ける | 通知、同期、健康データなどの既存設定に到達できる。戻ると同じ画面・日付に復帰 |

**表示例**　運動枠は「筋トレ　15分 → 5分」と「元に戻す」。変更理由を開くと「明日の締切前に作業時間を確保」と表示する。朝食は料理名と短い見出し「食べたもの」で選択の意味を示し、「食べない」も同じ画面に置く。有意な状態は文字でも示し、色やアイコンの意味を暗記させない。

## 類似研究と適用範囲

| 研究・資料 | 根拠として使える点 | 今回への適用と限界 |
|---|---|---|
| [Refanidis & Yorke-Smith, SelfPlanner, 2010](https://doi.org/10.1145/1869397.1869401) | 個人活動の所要時間、分割の可否、場所・移動、時間制約、選好を制約付き最適化問題として定式化。優先順位を改善しながら配置するヒューリスティックを評価 | 個人の日程を直接扱う先例。運動の通常・短縮を選択肢にする発想に近い。体調から望ましい運動量を決める臨床的根拠は扱わない |
| [Berryほか, PTIME, 2011](https://research.tudelft.nl/en/publications/ptime-personalized-assistance-for-calendaring/) | 会議調整で利用者の要件・選好を表し、制約推論と個人化を組み合わせる | 自動枠と本人が明示的に選んだ枠に異なる権限を与える参考。訂正が一度あっただけで永続的な好みにしない |
| [Klasnjaほか, HeartSteps](https://doi.org/10.1093/abm/kay067) | 歩行の提案後30分の歩数は提案なしより増えたが、効果は時間とともに低下。座位を中断する提案では同じ指標の効果を検出できなかった | 介入しない選択とタイミングの評価に使える。歩数の短期効果から、外出後の余力、長期の体力、締切への効果を推定しない |

## 現行処理を基準にした技術案

現行の配置には開始30分以内の枠の保護、固定枠、日の余白、締切不足時に任意習慣を解放する処理がある。負荷は候補の点数にも反映される。比較基準にはこの挙動を使う。[planner.ts](../../src/lib/scheduler/planner.ts)・[dayload.ts](../../src/lib/scheduler/dayload.ts)

1. **候補を作る。** 一つの自動運動枠に通常・短縮・延期・見送りを用意する。時間割が変わった時点から既存の計画期間内で再評価し、締切が翌日の場合も含める。実施済み記録は確定。本人指定の運動と固定予定が衝突すれば、両方を表示して本人に選択を戻す。
2. **比較する。** 時間の重複、固定予定、睡眠・移動などの制約を守る。残る候補で締切までに入らない作業分数、連続した作業時間、本人の疲れ、当週の運動機会、既存枠を動かす件数・分数を見る。負荷と締切を一つの「体力点」に換算しない。例として、締切・体調を守れる候補の中で週の運動機会を保ち、同程度なら変更の少ない案を採る。予定が逼迫して全案で不足する場合は不足を明示する。余裕の見積もりが少し変わるたびに同じ枠が伸縮しないようにする。
3. **初版で比べる方式。** 現行プランナーに少数の運動候補を渡して再計算し、結果を比較する方式なら既存の規則を引き継げる。複数日の運動配置とタスク分割の組合せで局所的な判断が破綻する場合は、CP-SATで各候補の採否、開始時刻、長さ、重複禁止を表す小規模な参照モデルを用意し、解の質と計算時間を比較する。CP-SATの採用は評価後に判断する。[OR-Toolsの時間区間・重複禁止の例](https://developers.google.com/optimization/scheduling/job_shop)
4. **何をもって改善とするか。** 同じ架空の週を現行方式と候補比較方式に入力する。締切前、外出延長、疲労未入力、本人指定枠との競合、連日多忙、夜の予定追加を含める。固定枠の無断変更・実績の二重計上は0件。締切不足分数、当日予定の変更件数、確保できた運動機会、計算時間を並べる。利用後は取り消しの多さと「外出後の余力」等を任意で見直す。計算上の改善と生活上の改善はそれぞれ検証する。

## スマホでの受け入れ確認

朝食を1操作で記録して訂正できる。帰路にホームを経由せず買い物リストを開ける。週を横に送ってもタスク画面に切り替わらない。カレンダーから記録・設定を往復しても見ていた日付に戻る。運動の自動短縮は変更と取り消しを短く示し、本人指定の運動の変更には確認がある。文字拡大時とスワイプを使わない操作でも同じ目的を達成できる。
