検証: `npm test` 128件成功、`npm run lint` 成功、`npm run build` 成功（TypeScript検査・27ページの生成を含む）。

再現テストは `src/lib/review-regression.test.ts`、同期の画面・フックのテストは `src/lib/mock/store.test.tsx`、通知の再試行・同時実行・旧記録互換のテストは `src/lib/push/delivery.test.ts` に保存しています。テスト用に Testing Library と jsdom を開発依存関係へ追加しました。

DBのスキーマ変更やSQLの手動実行は不要です。通知は既存の `push_sent` に端末別の送信済みキーと期限付きの処理中キーを保存します。

本番反映後に確認する項目:

- iPhoneで起動・予定編集・アプリ復帰・オフラインからの復帰。
- 実端末へのWeb Pushと、外部カレンダーの実接続。
- 外部カレンダー未登録時の定期再計算・iCal配信。

上記の実サービス操作はローカルテストでは実施していません。送信成功直後、成功記録の保存前にプロセスが停止するケースでは、再送による重複の可能性が残ります。外部への送信とDB更新を1つの取引にできないためです。通常の送信エラー・重なった定期実行はテストしています。

保持する実績は今後増えます。残高を維持するための方針であり、将来履歴を圧縮する場合は、獲得済み金額を別途保存してから行う必要があります。旧版ですでに削除された履歴をこの修正だけで復元することはできません。
