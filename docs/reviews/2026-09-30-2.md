## 配置エンジン（`src/lib/scheduler/planner.ts`）

- **S1 [P1] 「週に何回か」の習慣が毎日入る**（`chooseHabitDays` 724–751、`previous` の絞り込み 142）
  週を「今日から7日」で区切り、前の日にやった分を数えないため、毎日の組み直しで今日が選ばれ続ける。家での運動（週3回）を7日続けて朝8時に組み直すと7日とも入った。
  直し方: 週を月曜始まりにそろえ（`outlook.ts` と同じ）、今週すでにやった日（始まった枠、`habitLogs` の記録）を引く。前の日の枠は組み直しで消えるので、やった日を data の新しい項目に残す（`replan` で始まった枠の日を記録、14日より古いものは削る。`DATA_KEYS`・既定値・読み込みにも足す）。
- **S2 [P1] 「洗濯を回す」が始まったあとの組み直しで「干す・取り込む」が消える**（147、282–291、437–447）
  回す枠は始まったので残るが、干す枠はまだなので動かせる扱いになり、`placeByInterval` は今日やったとみなして置き直さない。その通知も毎時の組み直しで消える。
  直し方: 親の枠（`title === habit.name` で `finish` あり）を残すなら、干す枠も残す。待ち時間を `waits` に登録し、子（片付け）がもうその待ち時間にあるなら重ねて置かない。
- **S3 [P1] 身支度のある日（外出・会議リンク）に朝食と散歩が消える**（327 の `cueAt` の `routine`）
  きっかけの時刻が「起床＋朝ルーティン」で、身支度の分を含まない。朝ルーティン・身支度の枠と重なり、時間帯に入らない。見本のデータでは水・金に毎回起きる。
  直し方: 「起床＋朝ルーティン＋（身支度の日は）身支度」を使う。203・210・484 にも同じ式があるので1つの関数にまとめる。
- **S4 [P2] 0時〜就寝の間に組み直すと、今夜の残りが消える**（124–134）
  `days` が暦の今日から始まり、前の晩（就寝が夜中）の日が入らない。既定の就寝 2:00 だと、毎時5分の組み直し（0:05・1:05）で 1:30 の「寝る準備」の通知が push_schedule から消える。
  直し方: 前の日の就寝が今より後なら、前の日から `days` を始める。当日の終了済み習慣を残す判定（142 の `b.start >= firstDay`）もその日の始まりを基準にする。`dayPlans[0]` を暦の今日と決めつけている所がないか確認（`recovery.ts:64` と `outlook.ts:41` は探し方が日付なので問題ない）。
- **S5 [P2] 0時を過ぎてから始まった入浴が、次の日の分に数えられる**（456–457、661、680）
  暦の日で「その日にもう置いたか」を見ているため、次の晩に入浴が入らない。
  直し方: 暦の日ではなく `dayOf(b.start)`（起床〜就寝）で、どの日の枠かを決める。
- **S6 [P2] 片付け（`duringHabitId` の子）が「今日は飛ばす」と「疲れている」を無視する**（384–393）
  直し方: 待ち時間の繰り返しの中で `skipped(habit, その日)` を見る。
- **S7 [P3] 0時過ぎの帰宅が、次の日の帰宅時刻にもなる**（198。`rhythm.ts:92` の休日の判定も同じ）
  帰宅時の体力を「少ない」と答えると、次の日が一日じゅうタスクなしになることがある。
  直し方: `r > d.wake` にする。休日の判定は4時以降に始まる予定だけで見る。

## 保存と同期

- **D1 [P1] 自動の取り込みが終わる直前の編集が、サーバーに保存されない**（`store.ts:137` の `fromRemote`、193–201）
  開いた直後や15分以上たって戻ったときに、取り込みが終わる0.8秒以内に操作すると、保存の予約が消えて保存されない。ほかの端末で編集すると消える。
  直し方: 保存待ちの編集があるときは、`fromRemote` の場合も保存し直す（`dirty` のような ref を使う）。
- **D2 [P1] Notion: ある段階のタスクを完了にすると、同じ行の次の段階が取り込まれない**（`mock/notion.ts:32`）
  ID が行ごとに1つ（`notion-<行>`）なので、完了の記録が次の段階も止める。
  直し方: 完了の記録に段階と締切を持たせ、両方同じときだけ飛ばす（または ID に段階を含める）。
- **D3 [P2] Notion: 同期が、自分で変えた所要時間（範囲・わからない）を上書きする。段階が変わっても前の残り時間が残る**（`mock/notion.ts:41–46`）
  直し方: `autoDuration` があるときだけ自動で入れる。段階か締切が変わったら `remainingMinutes` を消す。
- **D4 [P2] ご褒美の残高が、習慣の時間を延ばしたり習慣を消したりすると、さかのぼって減る**（`stats.ts:77`、`markValue` 11）
  直し方: 記録したときの金額（か所要時間）を残す。
- **D5 [P3] ご褒美が「記録する」以外の習慣も数える**（`stats.ts:77`）
  `RewardRates` の説明と記録ページは「記録する」の習慣だけ。カレンダーの枠からは、どの習慣にも「やった」を付けられる。説明に合わせて「記録する」の習慣だけにする。
- **D6 [P3]（未再現）Notion・天気の取得に失敗すると、保存のたびに取りにいく**（AppShell の effect。`fetchedAt` が進まない）
